# PSIS 농약 데이터 구조와 백엔드 연동 아이디어

다음과 같은 구현을 상정하고 데이터를 구조화, 적재하였습니다. 도움이 되길 바라며..

## 이 데이터를 구성한 배경

사용자가 식물 관리 상담 중 병해충이나 농약을 함께 물어볼 수 있다는 점을 고려해 PSIS 농약 등록정보를 별도 테이블로 정리했습니다.

예를 들면 다음처럼 질문이 이어질 수 있습니다.

```text
딸기 잎에 흰 가루가 생겼어
→ 어떤 병일 가능성이 있는지 확인
→ 딸기와 해당 병에 등록된 농약 정보 확인
→ 특정 제품의 사용법 확인
```

이 과정에서 자연어 검색과 정확한 사용정보 조회의 역할이 다르다고 보았습니다.

- 자연어 검색은 관련 작물·병해충·농약 그룹을 찾는 데 사용합니다.
- 희석배수, 사용 시기, 횟수와 독성 정보는 구조화된 원본 값을 사용합니다.

LLM이 제품별 사용기준을 추정하지 않도록 검색용 정보와 정확한 등록정보를 분리해 두었습니다.

## 테이블을 구성한 방식

농약 데이터는 `public.psis_pesticide_chunks`에 저장됩니다.

한 행은 다음 조합의 검색 그룹입니다.

```text
작물 + 대상 병해충 + 용도
```

예를 들어 `딸기 + 흰가루병 + 살균`이 한 행이 되고, 그 조건에 등록된 여러 제품의 상세정보는 같은 행의 `registrations` 배열에 들어갑니다.

현재 데이터 규모는 다음과 같습니다.

```text
농약 검색 그룹: 1,168행
제품별 등록정보: 13,158건
임베딩 차원: 1,536
```

주요 필드는 아래와 같은 용도를 생각하고 구성했습니다.

| 필드 | 활용 의도 |
|---|---|
| `crop_name` | 작물명이 명확한 질문의 정확 검색 |
| `target_disease_pest` | 병해충명이 명확한 질문의 정확 검색 |
| `use_type` | 살균·살충·제초 등 용도 구분 |
| `text` | 자연어 벡터 검색용 문장 |
| `embedding` | 관련 농약 그룹 검색 |
| `pesticide_names` | 제품명 검색과 목록 표시 |
| `active_ingredients` | 유효성분 검색 |
| `registration_count` | 그룹에 포함된 등록정보 수 |
| `registrations` | 제품별 사용법·독성 등 정확한 값 |
| `metadata` | 출처·분류·안전 태그 |

`text`에는 작물, 대상 병해충, 용도, 제품명과 유효성분이 들어 있습니다. 사용법 전체를 임베딩하지는 않았습니다.

`registrations`에는 다음과 같은 제품별 값이 보존되어 있습니다.

```text
제품명
유효성분
희석배수 또는 사용량
처리 시기와 방법
수확 전 사용기한
최대 사용 횟수
독성 및 어독성
제조·수입 업체
```

## 사용자 질문과 연결하는 흐름

백엔드에서는 질문에 명시된 정보를 우선 활용하고, 부족한 부분만 벡터 검색으로 보완하는 방식이 잘 맞을 것으로 생각했습니다.

```text
1. 질문 또는 등록 식물에서 작물명 확인
2. 질문에서 병해충명·제품명·성분명 확인
3. 명확한 값은 컬럼으로 정확 검색
4. 증상 중심이거나 표현이 모호하면 벡터 검색
5. 관련 그룹을 찾은 뒤 필요한 registrations만 선택
6. 선택된 구조화 값을 LLM에 전달
```

질문에 적힌 작물과 현재 등록된 식물이 다르다면 질문에 직접 적힌 작물을 우선하는 편이 자연스러울 것 같습니다.

### “딸기에 쓸 수 있는 농약들을 알려줘”

이 질문은 `crop_name = 딸기`로 정확 조회할 수 있습니다.

딸기에 연결된 모든 제품의 상세 사용법을 바로 전달하기보다는, 먼저 대상 병해충별 등록 건수를 보여주는 형태를 생각했습니다.

```text
딸기에 등록된 농약은 대상 병해충에 따라 구분됩니다.
- 흰가루병: 15건
- 잿빛곰팡이병: 12건
- 점박이응애: 18건

확인하려는 병해충을 알려주시면 제품명과 사용기준을 더 자세히 확인할 수 있습니다.
```

이렇게 하면 사용자가 필요한 범위를 먼저 선택할 수 있고, 13,158건의 등록정보가 한꺼번에 LLM으로 넘어가는 것도 피할 수 있습니다.

### “딸기 흰가루병에 등록된 농약 알려줘”

작물과 병해충이 모두 명확하므로 다음 두 필드로 관련 그룹을 찾을 수 있습니다.

```text
crop_name = 딸기
target_disease_pest = 흰가루병
```

첫 답변에는 `pesticide_names`, `active_ingredients`, `registration_count`를 활용해 제품 목록을 정리하고, 사용자가 특정 제품이나 사용법을 물었을 때 해당 제품의 `registrations`를 펼치는 흐름을 생각했습니다.

### “노바맥스는 어디에 쓰는 농약이야?”

제품명이 명확한 경우 `pesticide_names`에서 일치하는 그룹을 찾은 뒤, 작물과 대상 병해충을 보여줄 수 있습니다.

제품 사용법까지 요청한 경우에는 `registrations`에서 `brand_name`이 노바맥스인 항목만 골라 다음 값을 전달할 수 있습니다.

```text
active_ingredient
dilution_or_dose
application_timing
preharvest_interval
max_use_count
toxicity_name
fish_toxicity
```

### “메타 어쩌구 하는 농약 있잖아”

제품명을 일부만 기억하는 질문은 임베딩 검색만으로 안정적으로 찾기 어려울 수 있습니다.

제품명·성분명의 부분 일치 후보와 벡터 검색 결과, 현재 대화의 작물명을 함께 활용하면 후보를 좁힐 수 있을 것으로 보입니다. 후보가 여러 개라면 하나를 바로 확정하기보다 사용자에게 선택지를 보여주는 방식이 안전합니다.

### “딸기 잎에 흰 가루가 생겼는데 사용할 수 있는 약이 있어?”

이 질문은 기존 병해충 RAG와 농약 테이블이 함께 필요한 경우입니다.

```text
기존 rag_chunks에서 딸기와 증상 관련 병해충 문서 검색
→ 흰가루병 등 가능성 후보 확인
→ 딸기 + 후보 병해충 조건으로 농약 그룹 조회
→ 병해충 설명과 등록 농약 정보를 함께 구성
```

증상만으로 병명을 확정하기 어려우므로, 병해충 후보의 근거가 부족하면 농약 사용법을 바로 제시하기보다 사진이나 추가 증상을 요청하는 기존 상담 흐름을 유지하면 좋을 것 같습니다.

## 벡터 검색과 상세정보 조회

테이블에는 HNSW 벡터 인덱스까지 생성되어 있습니다. 벡터 검색 RPC와 실제 호출 로직은 백엔드에서 기존 RAG 구조에 맞춰 구현할 수 있도록 남겨두었습니다.

RPC 이름은 테이블명과 맞춰 다음과 같이 사용할 수 있습니다.

```text
match_psis_pesticide_chunks
```

벡터 검색 결과에는 `registrations` 전체를 포함하지 않는 편을 권장드립니다. 한 그룹에 등록정보가 최대 109건 들어 있어 검색 후보 여러 개를 한 번에 반환하면 응답과 LLM 컨텍스트가 커질 수 있습니다.

다음과 같은 2단계 조회를 염두에 두었습니다.

```text
1차: 벡터 검색으로 관련 chunk_id와 그룹 정보 확인
2차: 선택된 chunk_id의 registrations 조회
3차: 질문과 관련된 제품만 선택하여 LLM에 전달
```

벡터 검색의 1차 반환값은 아래 정도면 기존 검색 문서와 연결하기 편할 것으로 보입니다.

```text
chunk_id
source_id
title
text
metadata
similarity
```

## 기존 채팅 파이프라인과의 연결

현재 LangGraph 순서를 크게 바꾸기보다는 농약 검색 결과를 기존 `retrieved_docs`와 비슷한 형태로 변환하는 방식을 생각했습니다.

```json
{
  "content": "검색된 농약 그룹 요약 또는 선택된 제품 사용정보",
  "metadata": {
    "source_id": "PSIS source id",
    "title": "작물 병해충 등록 농약",
    "publisher": "농촌진흥청 농약안전정보시스템",
    "category": "pesticide_registration"
  },
  "score": 0.0
}
```

이 형태라면 기존 답변 생성과 출처 표시 구조를 상당 부분 재사용할 수 있을 것으로 보입니다.

```text
일반 생육·병해충 질문
→ 기존 rag_chunks 검색

농약 질문
→ psis_pesticide_chunks 추가 검색

병해충과 농약이 함께 필요한 질문
→ 두 검색 결과를 합쳐 답변 생성
```

정확 검색 결과가 있으면 이를 우선하고, 자연어 표현이 모호한 경우 벡터 검색을 보조적으로 사용하는 방향이 적합해 보입니다.

## 백엔드에서 보완해 주면 좋은 부분

현재 테이블은 검색과 상세 조회에 필요한 데이터를 제공하는 단계까지 준비되어 있습니다. 실제 사용자 입력을 안정적으로 연결하려면 백엔드에서 몇 가지 보완이 필요할 것으로 보입니다.

### 불완전한 제품명과 오타

현재 `pesticide_names`와 `active_ingredients`는 정확한 원본 이름을 담고 있습니다. 사용자가 이름을 정확히 입력하면 배열 검색으로 찾을 수 있지만, 아래와 같은 표현은 정확 일치만으로 처리하기 어렵습니다.

```text
메타 어쩌구 하는 약
노바 뭐였는데
에마멕틴 계열 약
```

이 경우에는 다음 후보를 함께 모아 순위를 정하는 방식이 적합해 보입니다.

```text
제품명 부분 일치
유효성분 부분 일치
영문 대소문자 정규화
벡터 검색 결과
현재 대화에서 확인된 작물명
```

후보가 여러 개라면 첫 번째 결과를 바로 제품으로 확정하기보다, 사용자가 선택할 수 있는 제품명과 적용 작물·병해충을 함께 보여주는 편이 안전합니다.

### registrations 응답 크기

한 그룹의 `registrations`에는 최대 109건이 들어 있습니다. 작물 하나에 연결된 여러 그룹의 JSONB를 한 번에 조회해 LLM에 전달하면 응답 크기와 토큰 사용량이 커질 수 있습니다.

다음과 같은 단계적 조회를 생각했습니다.

```text
작물 또는 자연어 질문으로 그룹 목록 조회
→ 병해충·제품명·성분명으로 범위 축소
→ 선택된 chunk_id의 registrations 조회
→ 질문과 관련된 제품만 LLM에 전달
```

“딸기에 쓸 수 있는 농약 전체”처럼 범위가 넓은 질문은 첫 답변에서 병해충별 건수와 일부 제품만 보여주고, 후속 질문에서 상세정보를 제공하는 형태가 적합해 보입니다.

### 같은 제품의 반복 노출

같은 제품이 서로 다른 작물·병해충·사용 조건에 등록되어 여러 그룹에 나타날 수 있습니다. 단순 제품 목록을 보여줄 때는 같은 제품명이 반복되지 않도록 정리할 수 있지만, 상세 사용법은 작물과 병해충 조건별로 유지할 필요가 있습니다.

```text
제품 목록
→ 같은 제품명 중복 정리 가능

사용법 안내
→ 작물 + 병해충 + 제품 조건을 함께 유지
```

제품 상세 레코드를 구분할 때는 `pesti_code`와 `disease_use_seq`를 함께 참고할 수 있습니다.

### 작물명과 병해충명 연결

NCPMS 병해충 문서와 PSIS 등록정보의 이름이 항상 완전히 같지는 않을 수 있습니다.

```text
봉숭아 / 봉선화
붓꽃 / 아이리스
진딧물 / 진딧물류
```

정확 일치 결과가 없을 때는 이름 별칭과 표기 정규화, 벡터 검색을 보조적으로 사용할 수 있습니다. 다만 유사한 이름만으로 다른 병해충을 같은 대상으로 확정하지 않는 것이 중요합니다.

### registrations 값 선택

LLM에 `registrations` 배열 전체를 맡겨 제품을 고르게 하기보다, 백엔드에서 먼저 사용자의 작물·병해충·제품명 조건에 맞는 레코드를 선택하는 편이 안전합니다.

```text
crop_name 일치
target_disease_pest 일치
brand_name 또는 active_ingredient 일치
→ 선택된 레코드의 구조화 값만 LLM에 전달
```

이렇게 하면 다른 작물이나 다른 제품의 희석배수와 사용 횟수가 답변에 섞이는 위험을 줄일 수 있습니다.

## registrations 누락값 확인 결과

normalized 농약 데이터의 13,158개 `registrations`를 전체 검사했습니다.

모든 레코드가 동일한 19개 필드 키를 가지고 있어 필드 자체가 빠진 행은 없었습니다. 그룹 검색에 사용하는 작물명, 대상 병해충명, 제품명 배열과 유효성분 배열도 누락된 그룹이 없었습니다.

다만 값이 빈 문자열이나 `-`로 제공된 항목이 있습니다.

| 필드 | 전체 | 사용 가능한 값 | 빈 값 또는 `-` | 참고 |
|---|---:|---:|---:|---|
| `max_use_count` | 13,158 | 9,174 | 3,984 | `-` 3,982건, 빈 문자열 2건 |
| `mode_of_action` | 13,158 | 13,125 | 33 | 빈 문자열 33건 |
| `preharvest_interval` | 13,158 | 13,156 | 2 | 빈 문자열 1건, `-` 1건 |

그 외 아래 필드는 누락·빈 문자열·단독 `-`가 확인되지 않았습니다.

```text
active_ingredient
active_ingredient_amount
application_timing
brand_name
company_name
detail_collected_at
dilution_or_dose
disease_use_seq
first_registration_date
fish_toxicity
manufacture_import_type
pesti_code
pesticide_name
toxicity_code
toxicity_name
wafindex
```

`max_use_count`의 `-`를 “횟수 제한 없음”으로 해석하지 않는 것이 좋습니다. 현재 수집된 등록정보에서 값을 확인하지 못한 상태로 표현하는 편이 안전합니다.

```text
현재 수집된 등록정보에서는 최대 사용 횟수를 확인하지 못했습니다.
```

`preharvest_interval`에는 `수확7일전` 같은 값뿐 아니라 `잡초발생기`, `발생초기`, `정식기`, `파종기`처럼 생육·처리 시기를 나타내는 값도 들어 있습니다. 모든 값을 숫자 일수로 변환하기보다 원문을 우선 표시하는 편이 적합합니다.

`dilution_or_dose`는 희석배수와 면적당 사용량을 한 문자열에 함께 보존하고 있습니다.

```text
2000배 -
- 300㎖/10a
1000배 1ℓ/㎡
```

문자열 일부에 `-`가 포함됐다고 해서 전체 값이 누락된 것은 아닙니다. 백엔드에서 임의로 분해하거나 단위를 추정하기보다 원문을 그대로 표시하는 것을 우선으로 생각했습니다.

누락된 값을 LLM이 주변 제품 정보로 보완하거나 추정하지 않도록, 빈 값과 `-`는 미확인 상태로 전달하는 것이 좋겠습니다.

## 답변에 사용할 정보

LLM에는 질문과 관련된 그룹과 제품 정보만 전달하는 것을 전제로 데이터를 구성했습니다.

예를 들어 특정 제품의 사용법을 설명할 때는 다음처럼 선택된 한 제품의 구조화 값만 전달할 수 있습니다.

```json
{
  "crop_name": "로즈마리",
  "target_disease_pest": "꽃노랑총채벌레",
  "brand_name": "노바맥스",
  "active_ingredient": "Emamectin benzoate",
  "dilution_or_dose": "2000배 -",
  "application_timing": "발생 초부터 경엽처리",
  "preharvest_interval": "수확7일전",
  "max_use_count": "2회",
  "toxicity_name": "저독성"
}
```

이렇게 전달하면 LLM은 자연어 설명만 담당하고, 희석배수나 사용 횟수는 DB 값을 그대로 사용할 수 있습니다.

## 안전성과 출처

농약 정보는 사용 추천이라기보다 PSIS 등록정보 조회 결과로 표현하는 것을 전제로 했습니다.

- 작물과 대상 병해충이 일치한 등록정보를 사용합니다.
- 병명을 확정 진단하지 않습니다.
- 제품명이 비슷한 경우 하나를 임의로 선택하지 않습니다.
- 희석배수, 사용 시기와 횟수는 DB 값을 그대로 사용합니다.
- 실제 사용 전 제품 라벨과 농촌진흥청 최신 등록정보 확인을 안내합니다.
- 답변에는 농촌진흥청 농약안전정보시스템 출처를 표시합니다.

## 함께 확인해 보면 좋을 질문

연동 후에는 아래 질문을 기준으로 데이터가 예상대로 연결되는지 함께 확인하면 좋을 것 같습니다.

```text
딸기에 쓸 수 있는 농약들을 알려줘
딸기 흰가루병에 등록된 농약 알려줘
노바맥스는 어디에 쓰는 농약이야?
로즈마리에 노바맥스를 어떻게 사용해?
에마멕틴벤조에이트 성분 농약을 알려줘
딸기 잎에 흰 가루가 생겼는데 사용할 수 있는 약이 있어?
```

특히 다른 작물의 등록정보가 섞이지 않는지, 선택한 제품과 상세 사용법이 일치하는지, 출처와 안전 안내가 자연스럽게 포함되는지를 확인하고 싶습니다.
