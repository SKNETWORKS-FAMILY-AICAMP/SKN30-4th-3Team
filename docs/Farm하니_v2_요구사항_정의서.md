## 1. 문서 목적

본 문서는 3차 단위 프로젝트에서 개발한 Farm하니 v1을 기반으로, 4차 단위 프로젝트에서 확장·재설계한 Farm하니 v2의 기능 및 비기능 요구사항을 정의한다.

요구사항은 다음 산출물과 동일한 식별자(ID)로 연결하여 사용한다.

- 화면설계서
- 시스템 구성도
- API 및 데이터 설계 문서
- 테스트 계획 및 결과 보고서
- 최종 발표자료

## 2. 프로젝트 개요

### 2.1 프로젝트명

**Farm하니 v2 — 공식 농업 문서 RAG와 멀티모달·다중 LLM을 활용한 식물 및 텃밭 통합 상담 웹 애플리케이션**

### 2.2 주제

LLM을 연동하여 내·외부 공식 농업 문서를 검색하고, 사용자가 등록한 식물·텃밭 정보와 사진을 함께 활용해 근거 있는 관리 상담을 제공하는 웹 애플리케이션을 개발한다.

### 2.3 추진 배경

기존 식물 관리 서비스와 커뮤니티 상담은 답변을 받는 데 시간이 걸리며, 답변의 근거나 정확성을 사용자가 확인하기 어렵다. 또한 일반적인 LLM 상담은 사용자의 실제 식물 정보와 관리 이력, 공식 문서의 근거가 연결되지 않으면 환각이나 부정확한 처방을 생성할 위험이 있다.

Farm하니 v2는 사용자가 등록한 식물·텃밭 정보, 재배 기록, 사진을 공식 농업 문서 기반 RAG와 결합하여 다음 문제를 해결한다.

- 사용자의 실제 관리 맥락이 반영되지 않는 일반적 답변
- 출처가 없거나 질문과 무관한 문서를 사용한 답변
- 식물 한 개만 상담할 수 있어 텃밭 전체 환경을 함께 판단하기 어려운 문제
- 단일 외부 LLM 장애 또는 사용량 소진 시 상담을 계속할 수 없는 문제
- 정적 HTML 및 직접 DOM 조작이 혼재하여 기능 확장과 유지보수가 어려운 프론트엔드 구조

### 2.4 프로젝트 목표

1. 사용자 요구사항을 분석하고 PC·모바일 화면을 설계한다.
2. React 기반 프론트엔드와 FastAPI 기반 백엔드를 구축한다.
3. 텍스트와 이미지를 처리하는 멀티모달 LLM 상담을 구현한다.
4. 공식 문서 RAG를 통해 답변 근거와 출처를 제공한다.
5. OpenAI 모델과 로컬 모델을 선택하고 장애 시 대체할 수 있는 구조를 구현한다.
6. Supabase 기반 사용자 데이터, 문서, 벡터, 이미지 저장소를 연동한다.
7. 클라우드 환경에 프론트엔드·백엔드를 배포하고 통합 검증한다.

## 3. 버전 범위

### 3.1 Farm하니 v1 기준

Farm하니 v1은 React/Vite 실행 환경을 일부 사용했지만, `design/*.html` 정적 화면을 직접 렌더링하고 `querySelector`, `getElementById`, `innerHTML` 등의 DOM 조작을 연결하는 혼합형 구조였다.

v1의 핵심 범위는 다음과 같다.

- 단일 식물 프로필 및 관리 기록
- 식물 사진 기반 상담
- 전문가 상담 및 내 식물과 대화하기 모드
- 공식 문서 RAG 및 출처 표시
- GPT-4o-mini 기반 채팅·비전 처리
- Supabase 인증·DB·Storage·pgvector 연동

### 3.2 Farm하니 v2 범위

v2는 2026년 7월 6일 이후의 개선 작업을 대상으로 하며, 프론트엔드 전면 재설계의 핵심 커밋은 `f1fa9b7`이다.

v2의 주요 확장 범위는 다음과 같다.

- 정적 HTML/DOM 조작 중심 화면을 React 컴포넌트·상태 기반 구조로 재설계
- 식물 등록·수정·선택 삭제 및 사진 갱신 개선
- 텃밭 등록·수정·삭제·사진·재배 유형·소속 식물 관리
- 단일 식물 상담과 텃밭 상담의 통합 상담 UX
- OpenAI GPT-5.4·GPT-5.5·GPT-5.6 및 로컬 Qwen3-VL 모델 선택
- OpenAI 장애·키 소진 등을 대비한 로컬 LLM fallback과 Circuit Breaker
- 로컬 모델의 텍스트·이미지 멀티모달 처리
- 모바일 PWA 및 상담 설정 패널 등 반응형 UX 개선
- RAG 작물 일치 검증, 근거성 검증, 무근거 답변 차단 및 농약 안전 가드 강화
- 해외 생육 데이터 번역·정규화와 공식 병해충·농약 데이터 확장
- 프론트엔드와 FastAPI 백엔드의 Vercel 배포 구조 반영

### 3.3 제외 범위

다음 항목은 이번 프로젝트의 필수 구현 범위에서 제외한다.

- 병명 확정 진단 및 의료·농업 전문가를 대체하는 진단
- 특정 농약의 무조건적인 사용 지시 또는 법적 안전사용기준을 벗어난 처방
- 사용자 업로드 사진을 별도 동의 없이 모델 학습 데이터로 재사용하는 기능
- 로컬 LLM 모델 자체의 추가 학습 또는 파인튜닝
- IoT 센서의 실시간 자동 제어
- 결제, 쇼핑몰 및 농자재 구매 기능
- 앱스토어에 배포하는 네이티브 iOS·Android 애플리케이션

## 6. 기능 요구사항

우선순위는 다음 기준을 사용한다.

- **M(Must):** 제출 및 서비스 핵심 동작에 반드시 필요
- **S(Should):** 사용자 경험 또는 운영 안정성에 중요
- **C(Could):** 추가 개선 가치가 있으나 핵심 동작에는 영향이 적음

구현 상태는 2026-07-31 `develop` 브랜치를 기준으로 한다.

### 9.2 데이터 정합성 규칙

1. 모든 사용자 데이터는 `user_id` 또는 소유 관계를 통해 사용자와 연결한다.
2. 하나의 상담 세션은 단일 식물 또는 텃밭 중 하나만 대상으로 가진다.
3. 사진 메타데이터는 식물 또는 텃밭 중 하나에만 연결한다.
4. 단일 작물 텃밭은 대표 작물을 필수로 가진다.
5. 텃밭 삭제 시 소속 식물은 삭제하지 않고 `garden_id`만 해제한다.
6. RAG 청크는 하나의 출처와 연결되고 고유한 식별자를 가진다.
7. Citation은 답변 생성에 실제 사용된 문서만 포함한다.

## 10. 시스템 제약 및 운영 조건

1. OpenAI 임베딩을 사용하는 현재 구조에서는 OpenAI 채팅을 로컬 모델로 대체하더라도 임베딩 API 장애 시 키워드 검색 fallback이 사용될 수 있다.
2. 로컬 모델은 Vercel 내부에서 직접 실행하지 않고 외부 RunPod GPU 환경에서 실행한다.
3. RunPod Pod가 중단되면 로컬 모델은 사용할 수 없으며 UI는 이를 비활성 상태로 표시해야 한다.
4. RunPod Ollama 프록시는 HTTPS와 Bearer Token 인증을 사용해야 한다.
5. 실제 API Key, DB 비밀번호, Service Role Key, 로컬 프록시 토큰을 저장소에 커밋해서는 안 된다.
6. 농약 관련 정보는 참고 정보로 제공하며 제품 라벨과 공식 안전사용기준 확인을 우선한다.
7. 사용자 이미지는 상담 제공 목적 범위에서만 처리한다.

## 11. 핵심 사용자 시나리오 및 인수 기준

### AC-01 식물 등록과 사진 반영

1. 사용자가 로그인한다.
2. 식물 이름과 종류를 입력하고 첫 사진을 첨부한다.
3. 등록을 완료한다.
4. 대시보드와 상세 화면에 새 식물과 첨부 사진이 표시된다.
5. 사진을 변경하면 두 화면 모두 최신 사진을 표시한다.

**연결 요구사항:** FR-PLANT-001~007

### AC-02 여러 식물 선택 삭제

1. 사용자가 대시보드에서 전체 또는 일부 식물을 선택한다.
2. `선택 삭제` 버튼을 누른다.
3. 확인 후 선택된 식물만 삭제된다.
4. 버튼 문구는 줄바꿈되지 않고 쓰레기통 아이콘과 함께 표시된다.

**연결 요구사항:** FR-PLANT-008~009

### AC-03 단일·복합 텃밭 관리

1. 사용자가 단일 작물 텃밭을 선택하면 대표 작물을 입력한다.
2. 여러 작물 텃밭을 선택하면 등록된 식물을 배정한다.
3. 별명과 식물 종류가 함께 있는 식물도 한 건으로만 표시된다.
4. 텃밭 사진을 등록하고 수정할 수 있다.
5. 텃밭 삭제 시 식물 프로필은 유지된다.

**연결 요구사항:** FR-GARDEN-001~008

### AC-04 단일 식물 멀티모달 상담

1. 사용자가 상담할 식물을 선택한다.
2. 전문가 또는 내 식물과 대화하기 모드를 선택한다.
3. 사진과 질문을 함께 전송한다.
4. 사진이 사용자 질문 위에 표시된다.
5. AI 답변은 식물 정보·기록·사진 신호·검색 문서를 반영한다.
6. 사용자는 출처를 확인한다.

**연결 요구사항:** FR-CHAT-001~016, FR-VISION-001~005, FR-RAG-001~012

### AC-05 텃밭 멀티모달 상담

1. 사용자가 상담 범위를 텃밭으로 전환한다.
2. 텃밭을 선택하고 필요하면 사진을 첨부한다.
3. 텃밭 정보와 소속 식물 기록을 포함한 답변을 받는다.
4. 다시 단일 식물 상담으로 전환할 수 있다.

**연결 요구사항:** FR-CHAT-001~004, 017, FR-GARDEN-001~008, FR-VISION-001~005

### AC-06 모델 선택과 장애 대응

1. 사용자가 GPT-5.4, GPT-5.5, GPT-5.6 또는 Local 모델을 선택한다.
2. 연결 가능한 모델은 초록색, 연결되지 않은 모델은 빨간색 상태로 표시된다.
3. 선택한 모델이 상담 답변을 생성한다.
4. OpenAI 장애 및 fallback 설정 시 로컬 모델로 전환된다.
5. 두 제공자 모두 사용할 수 없으면 명확한 오류를 표시한다.

**연결 요구사항:** FR-LLM-001~010

### AC-07 근거 부족 및 근거성 검증

1. 검색 문서가 있는 질문은 해당 문서에 기반한 답변과 Citation을 제공한다.
2. 생성 답변이 근거와 일치하지 않으면 문서 기반 fallback으로 교체한다.
3. 검색 문서가 0건이면 공식 근거가 부족하다고 명시한다.
4. 무관한 문서를 강제로 출처로 제공하지 않는다.

**연결 요구사항:** FR-RAG-004~009

### AC-08 농약 안전 상담

1. 일반 관리 질문에는 농약 문서를 혼입하지 않는다.
2. 사용자가 농약·방제 내용을 직접 질문한 경우에만 관련 문서를 검색 범위에 포함한다.
3. 답변에는 전문가 확인, 라벨 확인, 안전사용기준 준수 안내가 포함된다.

**연결 요구사항:** FR-RAG-010~012

### AC-09 모바일 상담 UX

1. 모바일 화면 진입 시 채팅 영역이 우선 보인다.
2. 설정 버튼 하나로 설정 패널을 펼치고 접는다.
3. 하단 내비게이션에는 홈, 내 식물, 텃밭, AI 상담만 한 행에 표시된다.
4. 입력창, 첨부 버튼과 전환 버튼을 터치로 편리하게 조작한다.

**연결 요구사항:** FR-UI-003~008
