## 1. 문서 목적

본 문서는 Farm하니 v2의 React 프론트엔드, FastAPI 백엔드, Supabase, RAG 데이터, OpenAI·로컬 LLM과 배포 환경을 하나의 사용자 흐름으로 검증하기 위한 통합 테스트 기준을 정의한다.

테스트의 핵심 목적은 다음과 같다.

1. 요구사항 정의서의 기능·비기능 요구사항이 실제 화면과 API에서 연결되는지 확인한다.
2. 단일 식물과 텃밭의 등록·관리·상담 흐름에서 데이터 중복·권한 누락·화면 불일치를 찾는다.
3. GPT-5.4, GPT-5.5, GPT-5.6과 로컬 모델에 동일한 RAG 근거·출처·안전 규칙이 적용되는지 확인한다.
4. 근거 0건, 무관 질문, 농약 질문, 모델 장애 등 실패 조건에서도 잘못된 출처나 위장된 정상 답변을 반환하지 않는지 확인한다.
5. 데이터 수집·전처리·적재 결과의 재현성, 메타데이터, 라이선스, 안전 태그와 저장소 보안 정책을 검증한다.
6. PC·모바일 및 Vercel 배포 환경에서 제출 가능한 품질인지 판정한다.

## 4. 테스트 범위

### 4.1 포함 범위

- Supabase Auth 세션과 FastAPI JWT 검증
- 내 식물 등록·조회·수정·삭제, 사진 갱신, 관리 기록과 선택 삭제
- 단일·복합 텃밭, 대표 작물·사진, 기존 식물 배정과 중복 방지
- 단일 식물·텃밭 상담 전환, 텍스트·이미지 첨부, 세션·피드백
- 전문가 모드와 내 식물과 대화하기 모드
- 모델 선택·상태 표시·fallback·Circuit Breaker
- 텍스트 및 멀티모달 RAG, Citation, 작물 일치, 근거성 검증
- 근거 0건·무관 질문·농약 질문 안전 처리
- 데이터 수집·정규화·청킹·임베딩·적재·제외 결정
- Vercel 배포, PWA, PC·모바일 반응형과 접근성
- 사용자 소유권, 연관 삭제, Storage 업로드·정리

### 4.2 제외 또는 별도 검증 범위

- LLM 모델 자체의 학습 품질 평가와 파인튜닝
- 실제 농업 진단·치료의 의학적·법률적 적합성 보증
- RunPod 인프라의 장기 부하·비용 최적화
- 모든 브라우저·기기 조합의 전수 시험
- 원본 AI Hub 이미지와 대용량 외부 원본의 내용 전수 검수

## 5. 테스트 전략

### 5.1 증적 수준

| 코드 | 증적 수준 | 설명 |
|---|---|---|
| A | 현재 자동화 | `8262812`에서 pytest, TypeScript, Vite 빌드 등 직접 실행 |
| B | 실환경 API | 실제 Supabase·OpenAI·Storage를 연결한 API 통합 실행 |
| C | 배포 스모크 | Vercel URL과 정적 자산·PWA·health를 네트워크에서 확인 |
| D | 데이터 검증 | 최신 데이터 브랜치 코드·JSONL·DB 수치·라이선스·비밀값 점검 |
| E | 수동 UI | 인증 후 PC·모바일 화면을 사용자 시나리오대로 조작·캡처 |

한 시나리오가 자동화에서 통과했더라도 실서비스 외부 연동 또는 UI 조작이 남아 있으면 `부분 통과`로 판정한다.

### 5.2 테스트 유형

1. 정적 검증: 코드 문법, 타입, OpenAPI, 환경변수 노출, 데이터 스키마를 확인한다.
2. 자동 회귀: pytest와 프론트 빌드로 인증·RAG·fallback·안전 규칙을 반복 검증한다.
3. API 통합: 실제 JWT, Supabase DB·Storage, OpenAI 모델을 연결한다.
4. End-to-End: 로그인부터 등록·상담·삭제까지 PC와 모바일에서 수행한다.
5. 장애 주입: OpenAI 키 누락, timeout, RunPod 중단, 근거 0건을 재현한다.
6. 데이터 품질: 출처별 수량, 필수 메타데이터, 차원, 중복, 채택·제외 근거를 확인한다.

| 구분 | 환경 | 확인 항목 |

| 외부 LLM | GPT-5.4, GPT-5.5, GPT-5.6 | 모델별 응답·RAG 규칙·오류 처리 |
| 로컬 LLM | RunPod RTX 4090, Ollama, OpenAI 호환 프록시, `qwen3-vl:4b-instruct` | 상태 확인, 텍스트·이미지, fallback |

## 7. 시작·종료 및 중단 기준

### 7.1 시작 기준

- 테스트 대상 커밋과 배포 버전을 기록했다.
- 프론트·백엔드 의존성 설치와 환경변수 설정이 완료됐다.
- 테스트 계정 A·B와 삭제 가능한 테스트 데이터를 준비했다.
- Supabase·OpenAI·RunPod 상태를 확인했다.
- DB 백업 또는 테스트 데이터 정리 절차가 준비됐다.

### 7.2 종료 기준

- 필수 시나리오를 100% 실행했다.
- S1·S2 미해결 결함이 없다.
- 현재 커밋의 백엔드 자동 테스트와 프론트 프로덕션 빌드가 모두 통과했다.
- GPT-5.4·5.5·5.6과 로컬 모델의 공통 RAG 규칙을 확인했다.
- PC·모바일 핵심 사용자 흐름을 각각 1회 이상 완료했다.
- 데이터 출처별 DB 수량과 1,536차원 임베딩을 운영 DB에서 재확인했다.
- 테스트 결과, 미실행 사유, 잔여 위험과 재시험 결과를 보고서에 남겼다.

### 7.3 즉시 중단·차단 기준

- 원격 Git 이력 또는 프론트 번들에서 실제 비밀값이 발견됨
- 다른 사용자의 데이터 조회·수정·삭제 가능
- 병명 확정 또는 무근거 농약 직접 처방이 반복됨
- 삭제가 의도하지 않은 다른 사용자·식물 데이터까지 전파됨
- 운영 데이터 훼손 가능성이 있는 마이그레이션 오류

| IT-17 | 연관 삭제·Storage | 사진 업로드, Cascade, Storage 정리 | A+B | NFR-SEC-005, 데이터 정합성 규칙 |
| IT-18 | 배포·UX·성능 | Vercel/PWA, PC·모바일, 접근성, 응답 시간 | B+C+E | FR-UI-001~010, NFR-PERF-001~004, NFR-COMP·ACC |

### 10.2 시나리오별 주요 절차와 기대 결과

#### IT-02 인증·소유권

1. 계정 A로 로그인하고 보호 화면에 진입한다.
2. 토큰 없이 사용자 API를 호출해 401을 확인한다.
3. 계정 B로 계정 A의 식물·텃밭·세션 ID를 조회·수정·삭제한다.
4. 인증 서비스 장애를 모의해 503과 내부 오류 마스킹을 확인한다.

기대 결과: 인증 없는 접근은 거부되고, 다른 사용자 리소스는 존재 여부를 노출하지 않으며, 인증 실패와 서비스 장애가 구분된다.

#### IT-03~06 식물·텃밭

1. 사진이 있는 `김고구` 고구마와 토마토를 등록한다.
2. 토마토 사진을 변경하고 대시보드·상세·상담 대상의 이미지를 확인한다.
3. 단일 텃밭과 복합 텃밭을 각각 생성한다.
4. 복합 텃밭에 `김고구`를 배정하고 별명과 종류 때문에 2건으로 늘지 않는지 확인한다.
5. 텃밭 삭제 후 식물 자체가 유지되는지 확인한다.

기대 결과: 모든 화면에 최신 데이터가 표시되고, 텃밭 구성원은 식물 ID 기준으로 한 건만 존재한다.

#### IT-07~08 상담 화면과 이력

1. 단일 식물 상담과 텃밭 상담을 양방향 전환한다.
2. 텍스트와 사진을 첨부하고 전송 전 미리보기를 확인한다.
3. 전송 후 사진이 질문 위에 귀속되고 AI 답변 쪽에 잘못 표시되지 않는지 확인한다.
4. 상담 이력·출처·피드백을 재조회한다.
5. 내 식물과 대화하기 모드의 친근한 말투와 마지막 이모티콘 한 개를 확인한다.

기대 결과: 대상·모드·이미지·이력이 일관되며, 모바일에서는 채팅이 먼저 보이고 설정 버튼 하나로 패널을 열고 닫는다.

#### IT-09~12 모델·RAG·이미지

동일 질문과 이미지를 GPT-5.4, GPT-5.5, GPT-5.6, `qwen3-vl:4b-instruct`에서 실행한다.

확인 항목:

- 선택한 모델 ID가 실제 요청에 전달되는가
- 사용 가능 상태는 초록색, 불가능 상태는 빨간색과 문구로 표시되는가
- 검색 문서와 Citation이 모델 선택과 무관하게 동일한 정책으로 처리되는가
- 로컬 모델은 외부 서명 URL 대신 Base64 이미지 입력을 받는가
- OpenAI 장애 시 허용된 오류만 로컬 fallback을 수행하는가
- 양쪽 모델이 모두 실패할 때 일반 답변을 위장하지 않고 오류를 알리는가

#### IT-13 근거·범위

| 질문 유형 | 기대 결과 |
|---|---|
| 문서가 있고 관련성이 높음 | 문서 기반 답변과 실제 사용 Citation 표시 |
| 검색 결과가 0건 | 공식 근거 부족 명시, 추가 사진·기록 요청, Citation 없음 |
| 검색 후보는 있으나 무관함 | 후보를 강제로 사용하지 않고 근거 부족 처리 |
| `주식 투자` | 식물 문서 검색·Citation을 노출하지 않고 서비스 범위 안내 |
| `에어컨은 누가 발명했어?` | 토마토 등 무관 출처를 붙이지 않고 지식 근거 부족 또는 서비스 범위 안내 |
| 다른 작물 전용 문서 | 최종 근거에서 제외 |

#### IT-15~16 데이터

1. 최신 데이터 브랜치의 모든 Python 수집·전처리 파일을 문법 검사한다.
2. JSONL 파싱, 레코드 수, 필수 메타데이터와 `chunk_id` 고유성을 확인한다.
3. 운영 DB에서 출처별 건수 합계와 1,536차원 벡터를 직접 조회한다.
4. PlantSolve 98건 중 품질 기준을 통과한 28건만 적재됐는지 확인한다.
5. 템플릿 중복과 농약 안전 위험이 있는 EPPO·Perenual은 0건인지 확인한다.
6. Git 전체 이력과 프론트 번들에서 API 키·서비스 역할 키·프록시 토큰을 탐지한다.
7. 원본·임베딩·대용량 중간 파일이 Git에서 제외됐는지 확인한다.

기대 결과: 재현 가능한 코드와 적재 승인 자료만 남고, 비밀값과 금지 산출물은 원격 이력에 존재하지 않는다.

#### IT-18 배포·UX·성능

- 진입 HTML, JS, CSS, 아이콘, `manifest.webmanifest`, 서비스 워커가 200을 반환한다.
- PC 1440×1000과 모바일 390×844에서 SCR-01~09를 검증한다.
- 모바일 하단 내비게이션은 한 행의 4개 항목만 표시한다.
- 아이콘 버튼은 접근 가능한 이름과 키보드 포커스를 제공한다.
- 텍스트 상담은 30초, 이미지 상담은 60초 이내를 목표로 하며 SSE 진행 상태가 표시된다.

```powershell
# 백엔드 자동화
.\.venv\Scripts\python.exe -m pytest backend/tests -q --durations=10
```
